- [`model-routing-ux-design.html`](model-routing-ux-design.html) — **design + built (P1, settings half of P2):** per-job model routing — why one global `GENERATE_MODEL` is the wrong shape once v1 fronts four providers and customers arrive with their own keys; the three-tier model (Heavy / Standard / Light — named to avoid colliding with `thinking.py`'s Quick/Balanced/Deep dial), Duct's job→tier assignment, the shipped all-Google default triple (Gemini 3.1 Pro / 3.7 Flash / 3.5 Flash-Lite) and why it forced both a catalogue addition and an engine-default floor under the ladder; the three-level fallback (within-tier `resolve_fallback_models`, the user-authored cross-tier ladder and why the cross-provider hop `MODEL_FALLBACK` forbids is allowed here, then the engine floor); multimodal *output* vs input and the `MODEL_EMITS` table; video as a connector rather than a model; the `/settings/models` page that absorbs the Engine dialog and the provider key cards; and the `agents/tiers.py` + `GET /api/providers/status` contract. §10 records what is still unwired — no agent run reads the saved map yet
- [`agent-ports-and-events.md`](agent-ports-and-events.md) — **implemented:** the harness boundary — the six agent ports (tools, events, HITL, artifacts, session, model transport) and why there is deliberately no `AgentHarness` interface; the LangChain stability tiers that decide how much framework each agent adopts; the published SSE event contract with its AG-UI mapping; the `<duct_report>` → `<duct_artifact>` rename and its deploy order; OpenRouter as the OpenAI-compatible transport; and the pinned OpenTelemetry GenAI spans
- [`agent-harness-references.md`](agent-harness-references.md) — **reference:** the watch-list of coding-agent harnesses built in the open (Codex, OpenCode, pi) — why each matters to Duct's agent shell, the revision it was last read at, and findings pinned to `file:line` so a later reader diffs rather than re-reads. Rules that come out of a reading go into the area `AGENTS.md`; this records where they came from
- [`agent-evaluation.md`](agent-evaluation.md) — agent output QA: the LLM-as-judge / persona critique harness (`backend/tests/eval/`), judge biases + mitigations, and the eval landscape
- [`agent-memory-research.html`](agent-memory-research.html) — **research + design (Phases 1–3 built):** how ChatGPT, Claude, Claude Code, Hermes Agent and the memory frameworks (Mem0, Zep, Letta…) implement memory; the Duct model — user / project / artifact scopes in one bi-temporal `project_memories` table, agent `RememberFact`/`SearchMemory` tools, post-session consolidation, provenance chips and the project timeline. §07 carries the build status: the table, tools, timeline, consolidation, controls, the UX pass and Phase 3 retrieval that shipped, and what is still Phase 4+
- [`agent-memory-taxonomy-and-ux-patterns.md`](agent-memory-taxonomy-and-ux-patterns.md) — **reference:** the memory taxonomy the literature converged on (substrate, function, retrieval, consolidation, temporal validity, evaluation) and the product UX patterns for provenance, timelines, trust/control and proactive recall
- [`agent-memory-on-deepagents.md`](agent-memory-on-deepagents.md) — **design:** what the `deepagents` SDK gives us for memory (`MemoryMiddleware`, backends, summarization, skills), the gaps, how the Duct memory model wires into V1 (`DuctMemoryBackend` projection, `RememberFact`/`SearchMemory` tools, structured-output consolidation), and the open-source-only stack (no memory library; Postgres FTS / pgvector, SQLite / sqlite-vec). §5 records where the shipped build departed from this plan — plain tools on both harnesses, no middleware or backend projection yet
- [`autonomous-insights-agent-plan.md`](autonomous-insights-agent-plan.md) — **design:** rebuilding the insights agent from a six-step wizard + two-call pipeline into a session-shaped autonomous agent on `create_deep_agent` — connector discovery and in-chat connect/account prompts replacing the wizard, server-side credential resolution, memory tools, a verification subagent that proves the number before synthesising it, markdown-by-default artifacts, and a three-level autonomy ladder that reduces interruption without widening what may auto-apply
- [`desktop-adaptive-ui-review.html`](desktop-adaptive-ui-review.html) — **review (first fixes shipped):** the app UI audited against the Tauri window it ships in — why viewport breakpoints are the wrong tool inside `SplitWorkspace`'s resizable panes (container queries, Tailwind v4 `@container`), the absolute-vs-relative unit count and what `px` actually costs on desktop, two unaligned breakpoint systems, the WAI-ARIA window-splitter gaps and the pointer-capture bug that killed divider drags over the report iframes, plus the forked primitives (`CodeBlock`, the `Phase` enum, twelve spinners) now consolidated. §What I changed lists what landed; §What I would do next is the ordered backlog
- [`design-system-contrast-review.html`](design-system-contrast-review.html) — **review (findings only, 2026-09-06):** the app design system measured. The headline is a wiring bug the code cannot show you: `theme.css`'s `@theme inline` maps `--color-destructive`, `--color-success` and `--color-warning` but none of their `-foreground` partners, so those three utilities are never generated — which is why the Stop button renders body-foreground on red (3.13:1 light, 2.77:1 dark) and why the correct `.dark --destructive-foreground` added in the design pass is read by nothing. Plus the full WCAG matrix for every token pair in both themes, the palette classes that fail as text (`text-green-500` 2.2:1, `text-amber-500` 2.15:1), white-on-fill status chips, the light-only hex in `AuditReportV1`/`ads-report.css`, 121 raw `<button>` against 137 `<Button>`, 228 `text-[Npx]` sizes with 179 at 11px or below, 15 files with no `dark:`, and a responsive section (fixed grids at 375px, `sm:` inside container regions, iOS zoom on the audit form) that no other doc covers. Complements `app/DESIGN.md`'s *Known gaps* rather than restating it; §Recommended order is five shippable phases
