コーディングエージェント用のマーケティングスキル。
リポジトリはすでに所有しています。

Claude Code、Codex、Cursor、およびSKILL.mdを読み込むあらゆるエージェント向けのオープンソーススキル。最初のスキルであるlaunch-checkは、公開サイトとその背景にあるコードを読み込み、ローンチを100点満点でスコア化し、3つの修正に順位を付けます。

インストール 
npx skills add 5hirish/duct
またはプラグインとして
Claude Code
claude plugin marketplace add 5hirish/duct && claude plugin install duct@duct
Codex
codex plugin marketplace add 5hirish/duct && codex plugin add duct@duct

その後、エージェントに「サイトのローンチ準備はできている？」と尋ねるか、Claude Codeで/launch-checkと入力してください。

最初のスキル: launch-check

ページを読み込みます。次にコードを読み込みます。

01

サイトとリポジトリを読み込みます

最大10件の公開ページ、サイトマップ、すべてのカード画像、そしてその背後にあるコード（アナリティクスタグ、登録やダウンロードのイベント、headの生成元、ページ内の主張）をチェックします。

$ curl -sSL yoursite.com
  10 pages · sitemap · llms.txt
$ grep -rn "capture(" src/
  no event on the signup form
02

6つの領域を100点満点でスコア化

各指摘事項には、検出元のURLまたはファイル名と行番号が記載されます。確認できなかった項目は「未検証」とマークされ、失敗として処理されることはありません。

64/100要改善
03

3つの修正に順位を付け、許可を得て1つを適用します

ローンチ日に最も重要な3つの修正をdiff形式で提示します。必ず事前に確認を求め、コミット、プッシュ、デプロイを行うことはありません。

修正1を適用しますか？ (はい / いいえ / すべてスキップ)

はい

チェック対象

6つの領域、ローンチ時の損失に応じて重み付け。

誰にも計測できないローンチからは何も学べないため、計測が最も重要視されます。コードと矛盾する主張はローンチ日に真っ先に指摘されるため、次に主張が重視されます。

各領域は100点から始まります。FAILは-25点、WARNは-10点です。チェックできなかった項目は減点されず「未検証」として表示されるため、リポジトリが存在しない場合はスコアではなく信頼度が下がります。

  • 85–100 準備完了
  • 70–84 修正後に準備完了
  • 55–69 要改善
  • 55未満 準備未完了
  1. 25計測

    ローンチの単一アクションまで記録されますか？

  2. 20主張

    プロダクトはページやリリースノートに書かれている通りの動作をしますか？

  3. 20検索

    検索エンジンはすべての主要ページをインデックス登録し、説明できますか？

  4. 15ソーシャルカード

    共有リンクにタイトル、説明文、画像が表示されますか？

  5. 10回答エンジン

    ChatGPT、Perplexity、Claudeがそれを読み取って引用できますか？

  6. 10ファーストインプレッション

    最初の画面に対象者と行うべき操作が表示されていますか？

3つの修正点

基準をクリアした指摘事項は2点のみです。残りはブラッシュアップです。

  1. 同意ツールでは把握できないダウンロード数をカウントします。

    EEA、英国、スイスでは、アナリティクスはAcceptの後にのみ読み込まれ、バナーを無視した訪問者のdownload_startedは送信されないキューで待機します。ヨーロッパからのローンチ当日のダウンロード数は少なく記録されます。

    修正：コードなし。ローンチ当日にGitHubのリリースダウンロード数を下限として読み取り、download_startedと比較します。

  2. すべての訪問者にダウンロードがmacOS向けであると伝えるのをやめましょう。

    プラットフォーム別のラベル表示は/downloadでのみ動作するため、ホームページのボタンはWindows、Linux、スマートフォンの訪問者にも一律で「macOS版をダウンロード」と表示されます。

FAQ

インストールする前に。

対応しているエージェントは？

open skills CLI がインストールするあらゆるエージェント（Claude Code、Codex、Cursor、OpenCode、Gemini CLI、GitHub Copilot、Windsurf、Zed など）。スキルは Agent Skills フォーマットの1つの SKILL.md フォルダであるため、このフォーマットを読み込めるエージェントであればインストーラーなしで使用できます。Claude Code と Codex は、インストールボックスの下にあるコマンドを使用して、Duct の独自カタログからプラグインとしてインストールすることもできます。

サイトやコードがDuctに送信されますか？

いいえ。このスキルは、エージェントが自身のWebおよびシェルツールを使用して従う一連の指示です。経路にDuctのサーバーは存在せず、アカウントもAPIキーもありません。エージェントが読み込んだデータは、エージェントの要求が常に送信される場所、つまり既に使用しているモデルにのみ送信されます。

コードは変更されますか？

許可なしでは行いません。単独で書き出すファイルはレポートであるduct-launch-check.mdのみです。各修正は差分と確認として1つずつ提示されます。コミット、プッシュ、デプロイは一切行わず、.envやキーファイルを開くこともありません。

リポジトリを開いておく必要がありますか？

いいえ、ただしリポジトリがある方が優れています。コードなしでは公開ページのみをチェックし、計測領域の大部分は失敗ではなく未検証として返されます。イベントを送信しないダウンロードのように、ページの監査では提示できない指摘事項は、リポジトリから得られます。

SEO監査とはどのように異なりますか？

SEO監査はHTMLを読み取ります。launch-checkはその背景にあるコードも読み取り、ページが約束している内容とプロダクトの実際の機能を照合します。検索は6つの領域の1つです。キーワードクラスタや競合他社を含む完全なクロールを行うには、Ductの無料SEO監査を実行してください。

費用と所要時間は？

このスキルは無料で、MITライセンスです。お使いのエージェント自身のモデルで実行されるため、チェックにかかるコストはエージェントが10ページとリポジトリの一部を読み取る費用のみです。10ページで停止し、10分以内での完了を目指します。

インストーラーは何らかのデータをトラッキングしますか？

オープンソースであり当社の管轄外であるskills CLIは、skills.shリーダーボード向けにインストール数を匿名でカウントします。無効化するには、実行前にDISABLE_TELEMETRY=1またはDO_NOT_TRACK=1を設定してください。スキル自体は一切データを送信しません。

更新または削除を行うにはどうすればよいですか？

npx skills updateを実行すると最新バージョンに更新され、npx skills remove launch-checkで削除されます。インストールは実行したプロジェクト内に行われます。すべてのプロジェクトで利用可能にするには-gを追加してください。CLIにはNode.js 22.20以降が必要です。

次に追加されるスキルは？

リクエストの多いものです。GitHub Discussionsで、エージェントに任せたいマーケティングタスクを教えてください。
