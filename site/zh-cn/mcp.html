如何连接服务器

三步。然后提问。

01

打开工具箱

在 Duct 应用中，打开工具箱。预制服务器会列在那里，任何其他服务器都可以通过其地址连接。

02

选择一个服务器或粘贴其地址

选择 OpenSEO、PostHog、Notion、Linear、Railway 或 Cloudflare。对于其他任何服务器，粘贴服务器的 https 地址。

03

登录一次

如果服务器支持登录，则一键登录。如果不支持，请粘贴供应商提供的 API 密钥。Duct 会对其进行加密。

然后在聊天中提问。 智能体会查看你连接的服务器上的工具，调用合适的工具，并根据返回结果回答。

任何其他服务器

不在列表中？粘贴其地址。

Duct 连接到任何可以通过公共互联网访问的 MCP 服务器。以下是所需条件和不适用的情况。

连接
  • 一个通过 Streamable HTTP 提供 MCP 服务的公共 https:// 地址。
  • 当服务器发布 OAuth 发现并接受客户端元数据文档或允许动态客户端注册时，可一键登录。
  • 否则，你粘贴的 API 密钥将作为 bearer token 发送到服务器。
不支持
  • 在你自己的电脑上通过 stdio 运行的本地服务器。
  • 私有网络上的服务器。托管服务只调用公共互联网地址。
  • 只接受预批准客户的供应商。Figma 和 Slack 目前就是这样运作的。

智能体会做什么，不会做什么

只读运行。其他所有操作都会先询问。

你连接的每个服务器都遵循相同的规则，但有一个区别：通过地址添加的服务器会在每次调用前询问。

只读工具立即运行

当 OpenSEO、PostHog、Notion 或 Linear 将工具标记为只读时，智能体会直接调用，无需询问。Railway 和 Cloudflare 不会获得这种信任，因为它们的读取可能会返回你的秘密，你通过地址添加的服务器也不会：每次调用这些工具都会先询问。

其他一切都等你确认

任何其他调用都会暂停并向你显示它将发送的所有内容。批准或跳过它。

回复是数据，而非指令

服务器返回的内容被视为可读取的数据，绝不是要遵循的指令。

你的令牌永远不会到达模型

登录信息和 API 密钥保留在 Duct 端，经过加密，绝不会展示给模型。

你的服务器，你的聊天

服务器属于连接它的人，并且只有他们自己的聊天会在任何项目中用到它。与你共享项目的人连接他们自己的服务器，并且永远不会读取你的。

目前仅用于洞察聊天

目前，已连接的服务器用于洞察聊天。预定的简报和 Content Studio 尚未调用它们。

故障排除

当服务器拒绝时。

它显示“此服务器需要 API 密钥”

该服务器不提供 Duct 可用的登录方式。请在供应商设置中创建 API 密钥并粘贴到工具箱中。

它显示“需要重新连接”

登录已过期，或在供应商端被撤销。请在工具箱中按“重新连接”并再次登录。

它显示“Duct 只连接到公共互联网上的服务器”

该地址指向你自己的电脑或私有网络。托管服务只调用公共互联网地址，因此无法访问本地或内部服务器。

为什么我无法连接 Figma 或 Slack？

两者都只接受他们预先批准的客户端，因此仅凭服务器地址是不够的。它们尚不与 Duct 配合使用。

工具调用会产生费用吗？

有些会在供应商端产生费用。例如 OpenSEO 研究等需要消耗积分的调用，会消耗你在该供应商处的积分，与通过其他客户端调用相同。

这与 Claude 和 ChatGPT 连接器有何关系

他们的目录大多列出了相同的供应商 MCP 服务器。Duct 可以直接连接这些服务器，并使用你提供的任何模型。
