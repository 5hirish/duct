自行运行

克隆它。添加一个密钥。启动两部分。

后端是 FastAPI，应用是 Next.js，一个 Makefile 驱动两者。将模型提供商密钥添加到 env 文件，你就能在几分钟内从自己的机器读取自己的工具。

《README》是设置的权威指南，它也涵盖了内置后端（磁盘上的 SQLite，仅回环，无需账户）的桌面构建。CONTRIBUTING.md 列出了 CI 运行的检查。

终端 
$ git clone https://github.com/5hirish/duct.git && cd duct
$ make setup
$ cp backend/.env.example backend/.env.local   # add one model provider key
$ make serve-backend                            # then, in a second terminal:
$ make serve-app

什么会产生费用

免费，自带密钥。始终如此。

MIT 许可证不是试用版。 智能体、连接器和审批门是产品，它们都在代码库中。使用你自己的模型密钥，或使用你已付费的 ChatGPT 计划运行它们，你无需向我们支付任何费用。

未来将推出捆绑模型的付费计划，这样团队就可以在无需任何人持有 API 密钥的情况下使用 Duct，并且是在桌面应用已连接的托管服务之上。今天已开源的内容不会转为付费。如果发生任何变化，本页面会在代码之前说明。

问题

人们真正会问的问题

Duct 真的免费吗？

是的。Duct 采用 MIT 许可证，使用你自己的模型密钥是免费的，这一点不会改变。你直接向你的模型提供商付费，或者使用你已有的 ChatGPT 计划登录。付费计划稍后会为不愿持有密钥的团队捆绑模型访问权限；目前开源的功能不会因此变为付费。

我可以在没有账户的情况下运行 Duct 吗？

是的。克隆仓库，运行 make setup，添加一个模型提供商密钥，然后启动后端和应用。所有内容都保留在你的机器或服务器上，不涉及 Duct 账户。

我可以使用 Duct 进行商业用途或分叉它吗？

是的。MIT 许可证允许商业使用、修改和再分发。唯一的例外是 docs/guides 下的第三方文档以及 Duct 名称和标志。

我如何贡献？

从 CONTRIBUTING.md 开始。问题和讨论在 GitHub 上，路线图是一个公开的项目看板，欢迎智能体撰写的贡献，只要拉取请求说明了智能体在哪里提供了帮助。
