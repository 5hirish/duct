The agent proposes. You approve.

Duct can prepare a change to your ads or analytics. No tool lets it approve one, so it cannot be talked into it.

Anything destructive waits for your click, at every setting.

A short list of reversible changes may apply on their own, and only if you turn that on.

Rent the agent framework. Never marry it.

Agent frameworks change every week. Duct's prompts, tools and scoring are plain Python, and a test fails if a framework import appears outside the few adapter files.

Abstract on the second use.

One implementation is a guess. Two is a fact. The shared adapters were pulled out when a second agent needed them, and the allowlist says which one.

An API key is not permission.

The app's key ships to the browser, so it proves which app is calling, never who. Every project route checks that you are a member, and a stranger gets a 404.

A test walks every route and fails on one without a signed-in user, unless a written reason sits beside it.

Your keys, your choice of model.

Bring a key from Anthropic, OpenAI, Google, xAI or OpenRouter, or run a local model. You pick three models; Duct decides which job needs which.

The desktop app keeps your keys in the OS keychain. For no Duct servers at all, the self-host build runs the whole backend on your machine.

Comments carry the why.

A comment that restates the line below it teaches people to skip comments. The ones worth writing name the threat, the failure or the option that lost.

In code agents help write, that reasoning is what the next change gets checked against. STYLE.md cites this one as the model.

Agent-written pull requests are welcome.

The template asks where an agent helped, so the reviewer knows where to look hardest. Nothing is rejected for ticking it.

Disagree with one? Say so in public.

Each of these is a default with a reason. If the reason is wrong, the reason should change.
