O que ela verifica

Seis áreas, ponderadas pelo que um lançamento perde.

Um lançamento que ninguém consegue medir não ensina nada, por isso a mensuração tem o maior peso. Uma alegação contrariada pelo código vira o comentário principal no dia do lançamento, então as alegações vêm em seguida.

Cada área começa em 100. Um FAIL desconta 25 pontos e um WARN, 10. Algo que não pôde ser verificado não desconta nada e é listado como não verificado; assim, a falta de um repositório diminui a confiança, não a pontuação.

  • 85–100 Pronto
  • 70–84 Pronto após correções
  • 55–69 Precisa de ajustes
  • Abaixo de 55 Não está pronto

  2. 20Alegações

  3. 20Busca

  4. 15Card social

  5. 10Motores de resposta

    ChatGPT, Perplexity e Claude conseguem ler e citar o conteúdo?

  6. 10Primeira impressão

Três correções

Apenas duas constatações atingiram o critério. O restante é polimento.

  1. Conte os downloads que o consentimento nunca vê.

    No EEE, Reino Unido e Suíça, os dados analíticos só carregam após Aceitar, e download_started aguarda em uma fila que nunca é enviada para visitantes que ignoram o banner. Os downloads da Europa no dia do lançamento parecerão baixos.

    Impacto 2 · Esforço 1 · Encontrado por: repositório · site/assets/duct.js:364

    Correção: sem código. Leia a contagem de downloads da versão no GitHub no dia do lançamento como valor mínimo e compare com download_started.

  2. Pare de dizer a todos os visitantes que o download é para macOS.

    O botão da página inicial diz “Baixar para macOS” para visitantes no Windows, Linux e celular também, porque o rótulo por plataforma só roda em /download.

FAQ

Antes de instalar.

Com quais agentes funciona?

Qualquer agente no qual a CLI do open skills instala: Claude Code, Codex, Cursor, OpenCode, Gemini CLI, GitHub Copilot, Windsurf e Zed entre eles. A skill é uma pasta SKILL.md no formato Agent Skills, então um agente que leia esse formato pode usá-la sem o instalador. O Claude Code e o Codex também podem instalá-la como plugin a partir do próprio catálogo do Duct, com os comandos abaixo da caixa de instalação.

Ele envia meu site ou meu código para o Duct?

Não. A skill é um conjunto de instruções que seu agente segue com suas próprias ferramentas de web e shell. Não há nenhum servidor do Duct no processo, nenhuma conta e nenhuma chave de API. O que o agente lê vai apenas para onde as requisições dele sempre vão: para o modelo que você já usa.

Ela vai alterar meu código?

Não sem um sim. O único arquivo que ele grava sozinho é o relatório, duct-launch-check.md. Cada correção vem como um diff e uma pergunta, uma por vez. Ele nunca faz commit, push ou deploy, e nunca abre o .env nem arquivos de chaves.

Preciso de um repositório aberto?

Não, mas é melhor com um. Sem o código, ele verifica apenas as páginas públicas, e a maior parte da área de métricas volta como não verificada em vez de reprovada. As constatações que uma auditoria de página não consegue identificar, como um download que não envia eventos, vêm do repositório.

Como ele se diferencia de uma auditoria de SEO?

Uma auditoria de SEO lê o HTML. O launch-check também lê o código por trás dele e confere o que a página promete contra o que o produto faz. Busca é uma área de seis. Para uma varredura completa com clusters de palavras-chave e concorrentes, execute a auditoria gratuita de SEO do Duct.

Quanto custa e quanto tempo leva?

A skill é gratuita e tem licença MIT. Ela roda no próprio modelo do seu agente, então uma checagem custa o que o seu agente gasta para ler dez páginas e parte de um repositório. Ela para em dez páginas e busca terminar em dez minutos.

O instalador rastreia algo?

A CLI de skills, que é de código aberto e não é nossa, conta as instalações anonimamente para o ranking do skills.sh. Defina DISABLE_TELEMETRY=1 ou DO_NOT_TRACK=1 antes de rodar para desativar isso. A skill em si não envia nada para lugar nenhum.

Como atualizo ou removo?

npx skills update atualiza para a versão mais recente, e npx skills remove launch-check remove o skill. A instalação vai para o projeto onde você a executa; adicione -g para disponibilizá-la em todos os projetos. A CLI precisa do Node.js 22.20 ou posterior.
