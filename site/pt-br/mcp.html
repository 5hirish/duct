Como conectar um servidor

Três passos. Depois pergunte.

01

Abrir Conexões

No app do Duct, abra Conexões. Os servidores prontos estão listados lá, e qualquer outro se conecta pelo seu endereço.

02

Escolha um servidor ou cole o endereço

Escolha OpenSEO, PostHog, Notion, Linear, Railway ou Cloudflare. Para qualquer outro, cole o endereço https do servidor.

03

Entre uma vez

Um clique onde o servidor suporta o entrar. Onde não suporta, cole uma chave de API do fornecedor. Duct a mantém criptografada.

Depois pergunte no chat. O agente examina as ferramentas nos servidores que você conectou, chama a que se encaixa e responde com o que retorna.

Qualquer outro servidor

Não está na lista? Cole o endereço.

O Duct se conecta a qualquer servidor MCP que ele pode alcançar pela internet pública. Aqui está o que isso exige e o que não funciona.

Conexões
  • Um endereço https:// público que serve MCP via Streamable HTTP.
  • Entrar com um clique quando o servidor publica a descoberta OAuth e aceita um documento de metadados do cliente ou permite o registro dinâmico de clientes.
  • Caso contrário, uma chave de API que você cola, enviada ao servidor como um token de portador.
Não compatível
  • Servidores locais que executam via stdio no seu próprio computador.
  • Servidores em uma rede privada. O serviço hospedado só chama endereços públicos da internet.
  • Fornecedores que só admitem clientes pré-aprovados. Figma e Slack funcionam assim hoje.

O que o agente fará e não fará

Execuções somente leitura. Todo o resto pergunta primeiro.

As mesmas regras valem para cada servidor que você conecta, com uma diferença: um servidor que você adiciona pelo seu endereço pergunta antes de cada chamada.

Ferramentas somente leitura são executadas imediatamente

Quando um dos servidores prontos marca uma ferramenta como somente leitura, o agente a chama sem perguntar. Um servidor que você adiciona por endereço não recebe essa confiança: o Duct não o verificou, então cada chamada pergunta primeiro.

Tudo o mais espera por você

Qualquer outra chamada pausa e mostra tudo o que será enviado. Aprove ou pule.

Respostas são dados, não ordens

O que um servidor retorna é tratado como dados para leitura, nunca como instruções a seguir.

Seus tokens nunca chegam ao modelo

Entradas e chaves de API permanecem no lado do Duct, criptografadas, e nunca são mostradas ao modelo.

Seus servidores, seus chats

Um servidor pertence à pessoa que o conectou, e apenas os chats dela o usam, em qualquer projeto. Alguém com quem você compartilha um projeto conecta o próprio e nunca lê os seus.

O chat de insights, por enquanto

Hoje, servidores conectados são usados no chat de insights. Resumos agendados e Content Studio ainda não os chamam.

Solução de problemas

Quando um servidor diz não.

Diz “Este servidor precisa de uma chave de API”

O servidor não oferece um entrar que o Duct possa usar. Crie uma chave de API nas configurações do fornecedor e cole-a em Conexões.

Diz “Precisa reconectar”

O entrar expirou ou foi revogado no lado do fornecedor. Pressione Reconectar em Conexões e entre novamente.

Diz “O Duct só se conecta a servidores na internet pública”

O endereço aponta para seu próprio computador ou uma rede privada. O serviço hospedado só chama endereços públicos da internet, então um servidor local ou interno não pode ser alcançado.

Por que não consigo conectar Figma ou Slack?

Ambos só admitem clientes que aprovaram antecipadamente, então o endereço do servidor deles sozinho não é suficiente. Eles ainda não funcionam com o Duct.

Uma chamada de ferramenta custa algo?

Alguns sim, no lado do fornecedor. Uma chamada que custa créditos lá, como pesquisa OpenSEO, gasta seus créditos com esse fornecedor, da mesma forma que faria de qualquer outro cliente.

Como isso se relaciona com conectores Claude e ChatGPT

Seus diretórios listam principalmente os mesmos servidores MCP de fornecedores. O Duct se conecta a esses servidores diretamente, com qualquer modelo que você traga.
