A download that just opens

The desktop app is a thin shell now: no 470 MB download, no twenty-second wait while it boots, and sign-in works as soon as the window appears. Intel Macs are covered for the first time.

Desktop

  • A fraction of the download, and it starts straight away. The app used to carry an entire Python backend inside it. It renders Duct and talks to the hosted API instead, so there is nothing to unpack and nothing to wait for.
  • Intel Macs are supported again. The macOS build is universal, so one download runs on both Apple silicon and Intel.
  • Download links that keep working. The download page has a card per platform — macOS, Windows, Linux, Debian/Ubuntu — each on a permanent link, so a bookmark still resolves after the next release.
  • Windows installs receive updates. They had been checking and being told there was nothing, every time, because the update manifest was missing its Windows entry.
  • A sign-in that cannot finish says so instead of quietly signing you in on the web and leaving the desktop window where it was.

Models & agents

  • xAI is a provider in its own right, with Grok 4.6. Bring your own xAI key and the tier map you already set applies to it.
  • More models to assign to a tier: Gemini 3.8 Flash, Fable 5.1, DeepSeek V4 Pro and Kimi K3.
  • Web search works whichever model you brought. It is Duct’s own tool now, rather than a feature only some providers offer.
  • A long insights thread no longer dead-ends. When the provider says the request is too long, Duct compacts the conversation once and retries, instead of offering you “start fresh” an hour in.

Execution

  • A change your account is not allowed to make is refused up front. Duct used to find that out at apply time — after you had already approved it.
  • Duct records the permissions Google actually granted, so declining one during setup is visible immediately rather than surfacing as a failure later.

Security

  • A site that redirects somewhere private is no longer followed. Duct checks every redirect hop and the address each host resolves to, not only the URL it was given.
  • Provider errors stay out of the browser. A failed model call used to pass the provider’s own error text through to the page; you get a short reference that matches the server log instead.
  • Uploaded files can only be read from where they were stored, enforced at the point a file is opened rather than trusted at each call site.

Bring your own models

Duct no longer decides which model runs your work. Pick a tier once, plug in OpenRouter, or point the OpenAI slot at the subscription you already pay for.

Models & agents

  • Three tiers, one job map. Choose a Heavy, Standard and Light model in settings. Every agent job picks the tier it needs, so you are not selecting a model feature by feature.
  • OpenRouter is a first-class provider. One key, and the tier map you already set applies to everything behind it.
  • A ChatGPT subscription can drive the OpenAI slot — useful if you pay for the seat but not the API.
  • Hosted runs use your keys, not ours. The hosted deployment stopped quietly falling back to Duct’s own provider credentials.

Workspace

  • A command palette. One shortcut to jump between projects, connectors and agents — and you can bind your own shortcuts to the actions you repeat.
  • Insights opens on what changed instead of an empty prompt box waiting for you to think of a question.
  • Duct remembers the project you were in instead of resetting to the first one on every visit.
  • Named controls, announced states, visible focus across the app, for anyone driving Duct by keyboard or screen reader.

Connectors

  • The connector list now matches what a project can actually reach. Duct asks the server, rather than inferring availability from whichever keys happen to be saved.
  • Every connected source is counted — the “sources connected” figure had been counting two of them.

Desktop

  • Credentials a self-host build stores on your machine are encrypted with a key the app mints into your OS keychain.
  • Connecting through the browser reports success as success — it had been calling a completed connection expired.

Duct starts remembering

Project memory lands, so you stop re-explaining your business to every agent. The desktop app reaches Windows and Linux, and updates itself on all three.

Memory

  • Duct remembers per project. Positioning, competitors, what you corrected last week — carried into the next brief instead of pasted in again.
  • Every recalled fact shows where it came from, as a chip you can dismiss when it is wrong.
  • An off-switch per session for the times you want the agent working from a blank slate.
  • Consolidation keeps memory from growing into noise, and a timeline shows what Duct learned and when.
  • Seed a project from a file — drop in a positioning doc or competitor list and skip the cold start.

Desktop

  • Windows and Linux builds, with self-update on all three platforms.
  • Connect a data source in your own browser, where your password manager and existing Google session already are — not in a stripped-down app window.
  • Sign-in failures explain themselves rather than returning a blank server error.

Reliability

  • Crash capture, and outage explanations per platform, so “the brief is late” comes with a reason attached.

From insight to execution

A brief that tells you what to fix is half a product. Duct now proposes the change, shows you exactly what it would do, and applies it only at the autonomy level you set.

Execution

  • Agent-proposed change sets. Propose, preview against a guardrail, approve, apply, roll back — every step visible before anything touches a live account.
  • A three-rung autonomy ladder. Suggest only, approve each change, or let a narrow class apply itself. Raising a rung never widens what a proposal is allowed to touch.
  • A review queue you can work through, with a detail drawer and approval of part of a change set rather than all of it.
  • A structured activity log — the per-project audit trail of what was proposed, by whom it was approved, and what actually applied.

Connectors

  • Google Ads, across five read connectors, plus executors for the changes teams make most often.
  • Mixpanel, Microsoft Clarity and GrowthBook joined the catalogue.
  • Per-project connector-to-account mapping, so one workspace can point each connector at the right ad account or property.
  • Server-side connector credentials, and a Google Tag Manager connector for teams who would rather not hand out keys.

Artifacts

  • Briefs and reports that outlive the session. A versioned store with stable links, agent edits, version history and exports — so a report you liked is still there next month.

Duct runs on your machine

The desktop shell learns to carry a backend of its own. The build you download still talks to Duct’s cloud — but the same app, built with the backend inside it, now runs the entire loop on your machine with no account behind it.

Desktop

  • A local backend the shell can bundle and supervise. A self-host build ships the server and database inside the app, so a project runs with nothing behind it. The published build leaves it out and uses the hosted API.
  • macOS builds are signed with Developer ID and notarized — the DMG opens without a fight with Gatekeeper.
  • The app finds its own API address at runtime, so one build works against the local sidecar or a hosted backend.

Insights

  • A second audit engine you can select per request, with the existing one still the default — useful on the day a provider is having a bad time.

Workspace

  • Invite teammates to a project as collaborators.

Security

  • The security audit and secret-leak scan now block a release instead of reporting on one that already shipped.
  • Every open dependency advisory in the app cleared.

Desktop

Insights

Workspace

  • Channels and linked social accounts, so a post knows where it is going before you approve it.

Where this started: connect Google Ads, say what you are trying to learn, and get a written report back instead of another dashboard.

Connectors

  • Connect Google Ads over OAuth and choose which account Duct reads.
  • Sign in with Google, with privacy policy and terms in place from day one.

Insights

  • A goal-driven flow. Pick the question you are trying to answer and Duct assembles the queries for it, instead of asking you to build them.
