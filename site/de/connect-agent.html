Was es unterscheidet

Ein Connector übergibt deinem Agenten Zeilen. Duct übergibt ihm Antworten.

Viele Server leiten deine Daten einfach an einen Agenten weiter. Dann muss der Agent sie zusammenrechnen, den Kontext erraten und jedes Mal bei einem leeren Prompt anfangen.

Ein Rohdaten-Connector gibt ihmDuct gibt ihm
Zeilen, die es selbst zusammenzählen mussSummen und Raten, die Duct im Code abgeglichen hat, inklusive Zeitraum
Nichts vom letzten MalWas du entschieden, gestartet und gemessen hast, sortiert nach der Frage
Jedes Mal ein leeres PromptDucts eigenes Playbook mit Notizen dazu, wie jedes Tool falsche Zahlen meldet

Gebaut, um es an einen Agenten zu übergeben

Es erledigt die Arbeit. Du behältst die Schlüssel.

Agenten können durch das, was sie lesen, zu Dingen überredet werden. Wichtige Dinge liegen daher nie in ihrer Hand – egal, was du erlaubst.

Immer deins, in Duct
  • Das Freigeben oder Anwenden einer Änderung, das Veröffentlichen eines Beitrags, das Verbinden eines Tools. Kein Agent kann das, egal was du erlaubst.
  • Deine Passwörter und Schlüssel. Kein Agent sieht je eines davon.
  • Ein Protokoll von allem, was es speichert, unter Aktivitäten unter seinem eigenen Namen. Eine Bearbeitung lässt sich mit einem Klick rückgängig machen.
  • Text von einer Webseite, ein Suchbegriff oder ein Beitrag erreicht ihn als Daten markiert, niemals als Anweisungen.
  • Der Ausschalter. Trenne es in den Einstellungen und es stoppt beim nächsten Aufruf.

Einrichtung durch Agent

Acht Agenten. Eine Adresse.

Jeder Agent verbindet sich mit demselben Server. Wähle deinen für die genauen Schritte aus.

Claude Code

  1. Führe in deinem Terminal aus: 
    claude mcp add --transport http --scope user duct https://api.getduct.ai/mcp
  2. Führe in Claude Code /mcp aus, wähle duct und dann Authentifizieren.
  3. Dein Browser öffnet sich bei Duct. Wähle, was er tun kann, und klicke dann auf Zulassen.
  4. Führe /mcp__duct__insights_brief aus oder frage nach dem Briefing dieser Woche.

Codex

  1. Führe in deinem Terminal aus: 
    codex mcp add duct --url https://api.getduct.ai/mcp
  2. Dann anmelden: 
    codex mcp login duct
  3. Dein Browser öffnet sich bei Duct. Wähle, was er tun kann, und klicke dann auf Zulassen.

Cursor

  1. Füge Duct zu ~/.cursor/mcp.json hinzu: 
    {
  "mcpServers": {
    "duct": {
      "url": "https://api.getduct.ai/mcp"
    }
  }
}
  2. Drücke in Cursors MCP-Einstellungen die Anmeldeaufforderung auf dem Duct-Server.
  3. Dein Browser öffnet sich bei Duct. Wähle, was er tun kann, und klicke dann auf Zulassen.

Gemini CLI

  1. Füge Duct zu ~/.gemini/settings.json hinzu: 
    {
  "mcpServers": {
    "duct": {
      "httpUrl": "https://api.getduct.ai/mcp"
    }
  }
}
  2. Starte Gemini CLI und melde dich an: 
    /mcp auth duct
  3. Dein Browser öffnet sich bei Duct. Wähle, was er tun kann, und klicke dann auf Zulassen.
  4. Führe /insights_brief aus oder frage nach dem Briefing für diese Woche.

VS Code

  1. Öffne die Befehlspalette und führe MCP: Server hinzufügen aus.
  2. Wähle HTTP, füge die Adresse ein und nenne es duct: 
    https://api.getduct.ai/mcp
  3. VS Code fordert dich bei der ersten Nutzung von Duct zum Anmelden auf. Dein Browser öffnet Duct. Wähle aus, was es tun darf, und klicke dann auf Zulassen.

OpenCode

  1. Füge Duct zu opencode.json hinzu: 
    {
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "duct": {
      "type": "remote",
      "url": "https://api.getduct.ai/mcp"
    }
  }
}
  2. Dann anmelden: 
    opencode mcp auth duct
  3. Dein Browser öffnet sich bei Duct. Wähle, was er tun kann, und klicke dann auf Zulassen.

Claude, auf claude.ai oder Claude Desktop

  1. Öffne auf claude.ai oder in Claude Desktop Einstellungen → Connectors und wähle Benutzerdefinierten Connector hinzufügen.
  2. Nenne es Duct und füge die Adresse ein: 
    https://api.getduct.ai/mcp
  3. Klicke auf Verbinden. Duct öffnet sich in deinem Browser. Wähle aus, was es tun darf, und klicke dann auf Zulassen.

ChatGPT

  1. Aktiviere in ChatGPTs Einstellungen den Entwicklermodus.
  2. Füge einen Connector mit dieser Adresse hinzu und wähle OAuth zur Authentifizierung: 
    https://api.getduct.ai/mcp
  3. Duct öffnet sich in deinem Browser. Wähle, was es tun kann, und klicke dann auf Zulassen.

Ein anderer Agent? Wenn er einen entfernten MCP-Server über seine Adresse hinzufügen kann, gib ihm dieselbe. Wenn er sich nicht anmelden kann, verwende einen Token.

Zugriff

Jeder Agent ist aufgelistet. Trenne einen beliebigen.

Du siehst jeden verbundenen Agenten

Öffne in Duct Einstellungen → KI-Agenten verbinden. Jeder von dir erlaubte Agent ist dort aufgeführt, zusammen mit seinen Befugnissen und Projekten, und du kannst die Verbindung trennen. Ein getrennter Agent stoppt bei seinem nächsten Aufruf.

Kein Browser? Verwende ein Token.

Für CI, einen Remote-Rechner oder einen Agenten ohne Anmeldung. Erstelle einen auf derselben Einstellungsseite unter Kein Browser? Token verwenden mit denselben Optionen. Dein Agent sendet ihn als Header:

Authorization: Bearer duct_mcp_…

In Claude Code:

claude mcp add --transport http --scope user duct https://api.getduct.ai/mcp --header "Authorization: Bearer YOUR_TOKEN"

Fragen

Die Fragen, die gestellt werden. Dann die Lösungen.

Bevor du dich verbindest

Brauche ich einen API-Schlüssel?

Nein. Dein Agent läuft über den Tarif, den du bereits bezahlst, und Duct ruft dafür kein Modell auf. Ein gespeicherter Schlüssel wird nur für Bilder benötigt und für das, was Duct ohne dich ausführt, wie ein geplantes Briefing.

Welche meiner Tools kann er lesen?

Stripe, Meta Ads, Mixpanel, GitHub, RevenueCat, Clarity, GrowthBook, Apple Search Ads, RSS-Feeds und den Rest verbindest du in Duct. Google Analytics, Search Console, Google Ads und Tag Manager bleiben vorerst in Ducts eigenem Agenten, während Googles Richtlinie für externe KI-Assistenten bestätigt wird.

Kann es mein Werbekonto ändern?

Nur wenn du vorgeschlagene Änderungen aktivierst, und nur als Vorschlag. Es wartet in Ducts Prüfwarteschlange, bis du es dort freigibst. Kein Agent kann eine Änderung freigeben oder anwenden.

Sieht Duct meine Unterhaltung?

Nein. Duct sieht nur die Aufrufe, die dein Agent an Duct richtet, wie die angeforderten Daten und den Grund, aber nie den Rest deines Chats.

Wird ein Briefing ausgeführt, während mein Laptop geschlossen ist?

Nicht von deinem Agenten. Geplante Briefings laufen in Duct über einen gespeicherten Schlüssel, weil niemands Agent um 3 Uhr morgens läuft. Was dein Agent schreibt, landet in derselben Bibliothek.

Was ist insights_brief?

Ducts Playbook für ein Briefing als Slash-Befehl: /mcp__duct__insights_brief in Claude Code, /insights_brief in Gemini CLI. Frage in jedem anderen Agenten nach dem Briefing dieser Woche, und er ruft dasselbe Playbook auf.

Wenn etwas schiefgeht

Mein Browser hat sich nie geöffnet

Starte die Anmeldung selbst: Führe /mcp in Claude Code, codex mcp login duct in Codex, /mcp auth duct in Gemini CLI oder opencode mcp auth duct in OpenCode aus.

Es meldet, dass es sich nicht registrieren konnte, oder „unterstützt keine dynamische Client-Registrierung“

Aktualisiere deinen Agenten auf die neueste Version und versuche es erneut. Wenn es immer noch fehlschlägt, verbinde dich stattdessen mit einem Token.

Es hat funktioniert, und jetzt erhält es einen 401-Fehler

Du hast die Verbindung in Duct getrennt, oder die Anmeldung ist nach 90 Tagen Inaktivität abgelaufen. Melde dich erneut über deinen Agenten an.

Ein Tool, das ich erwartet habe, ist nicht da

Dein Agent sieht nur das, was du beim Anmelden erlaubt hast. Trenne ihn in Duct, verbinde ihn erneut und wähle „An meiner Seite arbeiten“.

Ich bat es, das Projekt einzurichten, und nichts änderte sich

Ein Entwurf überschreibt niemals, was du in Duct eingegeben hast. Er füllt nur leere Felder aus oder ersetzt einen früheren Entwurf. Prüfe die Projektseite in Duct.
