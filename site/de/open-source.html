01

Lesezugriff auf alles ist viel verlangt.

Duct liest deine Anzeigen, Analysen, Umsätze und Session-Replays zusammen. Ein Tool mit dieser Ansicht sollte keine Black Box sein. Jeder API-Aufruf und jeder Prompt ist im Repository, lesbar, bevor du etwas verbindest.

02

Der Freigabemechanismus lebt im Code, nicht in einem Prompt.

Der Agent kann eine Änderung vorschlagen und sie vorschauen. Er hat kein Tool, um eine freizugeben oder anzuwenden; das ist dein Button, und das Modell sieht ihn nie. Die Doktrin verknüpft jede Regel mit der Datei, die sie durchsetzt.

03

Eine Person kann nicht um Vertrauen bitten. Sie kann den Code zeigen.

Duct wird gebaut von einem Maintainer in Spanien, wobei Agenten den Großteil der Tipparbeit erledigen. Die Roadmap ist ein öffentliches Board, Entscheidungen werden in Issues diskutiert, und ein Pull Request von dir oder deinem Agenten erhält die gleiche Überprüfung.

Was wo läuft

Gleicher Code. Zwei Wege, ihn auszuführen.

Lade die App herunter und wir betreiben den Dienst dahinter: melde dich an, verbinde ein Tool, frage. Klone den Code und jeder Teil davon liegt in deiner Hand. Hier ist, was wo sitzt, in einfachen Worten.

Selbst betreiben

Klone es. Füge einen Schlüssel hinzu. Starte beide Hälften.

Das Backend ist FastAPI, die App ist Next.js, und ein Makefile steuert beides. Füge einen Modell-Provider-Schlüssel zur Env-Datei hinzu und du liest deine eigenen Tools in Minuten von deiner eigenen Maschine.

Die README ist die Quelle der Wahrheit für die Einrichtung und behandelt auch den Desktop-Build mit gebündeltem Backend: SQLite auf der Festplatte, nur Loopback, kein Konto. CONTRIBUTING.md listet die Prüfungen auf, die CI ausführt.

Terminal 
$ git clone https://github.com/5hirish/duct.git && cd duct
$ make setup
$ cp backend/.env.example backend/.env.local   # add one model provider key
$ make serve-backend                            # then, in a second terminal:
$ make serve-app

Was Geld kosten wird

Kostenlos mit deinen eigenen Schlüsseln. Immer.

Die MIT-Lizenz ist keine Testversion. Die Agenten, die Connectoren und das Freigabe-Gate sind das Produkt, und sie befinden sich im Repository. Betreibe sie mit deinen eigenen Modellschlüsseln oder mit dem ChatGPT-Plan, den du bereits bezahlst, und du schuldest uns nichts.

Was später kommt, ist ein kostenpflichtiger Plan, der die Modelle bündelt, damit ein Team Duct nutzen kann, ohne dass jemand einen API-Schlüssel besitzt, zusätzlich zum gehosteten Dienst, mit dem die Desktop-App bereits kommuniziert. Nichts, was heute Open Source ist, wird hinter diesen Plan verschoben. Sollte sich das jemals ändern, wird diese Seite dies mitteilen, bevor es der Code tut.

Fragen

Die, die Leute tatsächlich fragen

Ist Duct wirklich kostenlos?

Ja. Duct ist MIT-lizenziert und kostenlos mit deinen eigenen Modellschlüsseln, und das ändert sich nicht. Du bezahlst deinen Modell-Provider direkt oder meldest dich mit dem ChatGPT-Plan an, den du bereits hast. Ein kostenpflichtiger Plan bündelt später den Modellzugriff für Teams, die lieber keine Schlüssel halten möchten; nichts, was heute offen ist, wird dahinter verschoben.

Kann ich Duct ohne ein Konto betreiben?

Ja. Klone das Repository, führe make setup aus, füge einen Modell-Provider-Schlüssel hinzu und starte das Backend und die App. Alles bleibt auf deiner Maschine oder deinem Server, und kein Konto bei Duct ist involviert.

Kann ich Duct kommerziell nutzen oder forken?

Ja. Die MIT-Lizenz erlaubt kommerzielle Nutzung, Modifikation und Weiterverbreitung. Die einzigen Ausnahmen sind Dokumentationen Dritter unter docs/guides und der Duct-Name und die Marke.

Wie kann ich beitragen?

Beginne mit CONTRIBUTING.md. Issues und Diskussionen sind auf GitHub, die Roadmap ist ein öffentliches Projekt-Board, und von Agents verfasste Beiträge sind willkommen, solange der Pull Request angibt, wo ein Agent geholfen hat.
