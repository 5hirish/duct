Der erste Skill: launch-check

Er liest die Seite. Dann liest er den Code.

01

Liest die Website und das Repo

Bis zu zehn Live-Seiten, die Sitemap und jedes Card-Bild, dann der Code dahinter: das Analytics-Tag, das Registrierungs- oder Download-Event, woher der Head stammt und die Aussagen, die die Seite trifft.

02

Bewertet sechs Bereiche mit bis zu 100 Punkten

Jeder Befund nennt die URL oder die Datei und Zeile, aus der er stammt. Was nicht eingesehen werden konnte, wird als ungeprüft markiert, niemals als fehlgeschlagen.

03

Priorisiert drei Fixes, wendet einen bei einem Ja an

Die drei wichtigsten für den Launch-Tag, jeweils als Diff. Er fragt vor jedem nach und committet, pusht oder deployt nie.

Was er prüft

Sechs Bereiche, gewichtet nach dem, was bei einem Launch verloren geht.

Ein Launch, den niemand messen kann, bringt dir keine Erkenntnisse – daher wiegt die Messung am schwersten. Eine Behauptung, die dem Code widerspricht, ist am Launch-Tag der Top-Kommentar – daher kommen Behauptungen als Nächstes.

Jeder Bereich beginnt bei 100. Ein FAIL kostet 25 Punkte und ein WARN 10. Etwas, das nicht geprüft werden konnte, kostet nichts und wird als ungeprüft aufgeführt – ein fehlendes Repository senkt also das Vertrauen, nicht die Punktzahl.

Drei Fixes

Nur zwei Befunde haben die Hürde genommen. Der Rest ist Feinschliff.

  1. Zähle die Downloads, die die Einwilligung nie sieht.

    Im EWR, in Großbritannien und der Schweiz laden Analytics erst nach Accept, und download_started wartet in einer Warteschlange, die bei Besuchern, die das Banner ignorieren, nie gesendet wird. Downloads aus Europa am Launch-Tag fallen dadurch zu niedrig aus.

    Auswirkung 2 · Aufwand 1 · Gefunden durch: Repository · site/assets/duct.js:364

    Fix: kein Code. Lies die Download-Zahlen des Releases am Launch-Tag von GitHub als Untergrenze ab und vergleiche sie mit download_started.

  2. Hör auf, jedem Besucher zu sagen, dass der Download für macOS ist.

    Der Button auf der Startseite zeigt Besuchern mit Windows, Linux und Smartphones gleichermaßen „Download for macOS“ an, weil das plattformspezifische Label nur auf /download aktiv ist.

Kein Account

Keine Registrierung, kein API-Key, kein Duct-Login. Er nutzt die eigenen Web- und Shell-Tools deines Agenten und registriert sich nie, loggt sich nirgendwo ein und sendet keine Formulare ab.

Nichts an Duct gesendet

Der Skill besteht aus Anweisungen, ist kein Dienst. Deine Website und dein Code werden von deinem Agenten gelesen und nirgendwo sonsthin übertragen. Er öffnet niemals .env oder Schlüsseldateien.

Keine Änderung ohne ein Ja

FAQ

Bevor du es installierst.

Mit welchen Agenten funktioniert es?

Jeder Agent, in den die Open-Skills-CLI installiert: darunter Claude Code, Codex, Cursor, OpenCode, Gemini CLI, GitHub Copilot, Windsurf und Zed. Der Skill ist ein SKILL.md-Ordner im Format von Agent Skills, sodass ein Agent, der dieses Format liest, ihn ohne den Installer nutzen kann. Claude Code und Codex können ihn auch als Plugin aus Ducts eigenem Katalog installieren, mit den Befehlen unter dem Installationsfeld.

Sendet es meine Website oder meinen Code an Duct?

Nein. Der Skill ist eine Reihe von Anweisungen, die dein Agent mit seinen eigenen Web- und Shell-Tools befolgt. Es gibt keinen Duct-Server im Ablauf, keinen Account und keinen API-Key. Was dein Agent liest, landet nur dort, wo die Anfragen deines Agenten immer hingehen: beim Modell, das du bereits nutzt.

Wird er meinen Code ändern?

Nicht ohne ein Ja. Die einzige Datei, die er selbstständig schreibt, ist sein Bericht: duct-launch-check.md. Jeder Fix kommt einzeln als Diff und Frage. Er committet, pusht oder deployt nie und öffnet weder .env noch Schlüsseldateien.

Muss ein Repository geöffnet sein?

Nein, aber mit Code ist es besser. Ohne den Code prüft er nur die Live-Seiten, und der Großteil des Messbereichs gilt als ungeprüft statt als fehlgeschlagen. Die Befunde, die ein Seiten-Audit nicht liefern kann – wie ein Download, der kein Event auslöst –, stammen aus dem Repository.

Wie unterscheidet es sich von einem SEO-Audit?

Ein SEO-Audit liest das HTML. launch-check liest auch den Code dahinter und prüft, was die Seite verspricht, im Vergleich zu dem, was das Produkt tut. Suche ist einer von sechs Bereichen. Für einen vollständigen Crawl mit Keyword-Clustern und Mitbewerbern nutze Ducts kostenloses SEO-Audit.

Was kostet es und wie lange dauert es?

Der Skill ist kostenlos und unter MIT lizenziert. Er läuft auf dem Modell deines Agenten, ein Check kostet also so viel, wie dein Agent braucht, um zehn Seiten und einen Teil eines Repositorys zu lesen. Er stoppt bei zehn Seiten und zielt darauf ab, in zehn Minuten fertig zu sein.

Trackt der Installer irgendetwas?

Die Skills-CLI, die Open Source ist und nicht von uns stammt, zählt Installationen anonym für die skills.sh-Bestenliste. Setze vor dem Ausführen DISABLE_TELEMETRY=1 oder DO_NOT_TRACK=1, um das zu deaktivieren. Der Skill selbst sendet nichts irgendwohin.

Wie aktualisiere oder entferne ich es?

npx skills update bringt es auf die neueste Version, und npx skills remove launch-check entfernt es. Die Installation erfolgt in dem Projekt, in dem du es ausführst; füge -g hinzu, um es in jedem Projekt verfügbar zu machen. Das CLI benötigt Node.js 22.20 oder neuer.
